# قطرة — Frontend MVP

نموذج واجهة أمامية عربية (RTL) يحوّل متطلبات السبرنت الأول إلى تجربة قابلة للتصفح قبل ربطها بالـBackend.

## التشغيل

```bash
npm install
npm run dev
```

ثم افتح العنوان الذي يعرضه Vite (عادةً `http://localhost:5173`).

لإنشاء نسخة Production:

```bash
npm run build
npm run preview
```

## المسارات

- `#/` الصفحة التعريفية.
- `#/register` اختيار نوع الحساب.
- `#/register/donor` تسجيل متبرع.
- `#/register/organization` تسجيل مؤسسة.
- `#/login` تسجيل الدخول.
- `#/forgot-password` استعادة كلمة المرور.
- `#/supervisor/approvals` لوحة مشرف الجهة الصحية.
- `#/donor/dashboard` لوحة المتبرع.
- `#/donor/calls/details?id=DC-2026-001` تفاصيل نداء التبرع والاستجابة له.
- `#/donor/donations` سجل التبرعات المكتملة للمتبرع.
- `#/campaigns?role=donor` الحملات المتاحة للمتبرع.
- `#/account/profile?role=donor` الملف الشخصي للمتبرع.
- `#/account/profile?role=organization` الملف الشخصي للمؤسسة.
- `#/institution/dashboard` لوحة المؤسسة ومبدّل حالات الاعتماد.
- `#/institution/resubmit` تعديل الطلب المرفوض وإعادة تقديمه.
- `#/institution/blood-requests` بوابة خدمة طلب الدم المحمية.
- `#/institution/blood-requests/new` إنشاء طلب دم.
- `#/institution/blood-requests/details?id=BR-2026-0148` تفاصيل الطلب وتتبع حالته.
- `#/institution/blood-requests/edit?id=BR-2026-0148` تعديل الطلب إذا كان Pending.
- `#/institution/blood-bank` بوابة خدمة بنك الدم المحمية.
- `#/institution/blood-bank/inventory` إدارة وحدات المخزون.
- `#/institution/blood-bank/inventory/new` إضافة وحدة دم.
- `#/institution/blood-bank/alerts` تنبيهات النقص والصلاحية.
- `#/institution/blood-bank/requests` الطلبات الواردة.
- `#/institution/blood-bank/requests/details?id=BR-2026-0148` معالجة الطلب حتى التسليم.
- `#/donation-calls` إدارة نداءات التبرع للمؤسسة.
- `#/donation-calls/new` إنشاء نداء تبرع جديد.
- `#/donation-calls/target?id=DC-2026-001` البحث عن المتبرعين واستهدافهم.
- `#/donation-calls/responses?id=DC-2026-001` متابعة استجابات النداء.
- `#/donation-calls/record-donation?call=DC-2026-001&donor=D-1002` تسجيل تبرع مكتمل وإضافة وحدة للمخزون.
- `#/campaigns` الحملات العامة للزوار.
- `#/campaigns/details?id=CP-2026-0031&role=donor` تفاصيل الحملة والمشاركة.
- `#/institution/campaigns` إدارة حملات المؤسسة.
- `#/institution/campaigns/new` إنشاء حملة تبرع.
- `#/institution/campaigns/edit?id=CP-2026-0031` تعديل حملة قادمة.
- `#/institution/campaigns/participants?id=CP-2026-0031` متابعة المشاركين.
- `#/notifications?role=donor` مركز إشعارات المتبرع.
- `#/notifications?role=organization` مركز إشعارات المؤسسة.
- `#/supervisor/dashboard` لوحة مشرف الجهة الصحية.
- `#/supervisor/institutions` متابعة المؤسسات والخدمات.
- `#/supervisor/approvals` مسار مراجعة طلبات الاعتماد.
- `#/supervisor/blood-banks` متابعة بنوك الدم والمخزون.
- `#/supervisor/requests` متابعة طلبات الدم وحالاتها.
- `#/supervisor/donors` متابعة المتبرعين والتبرعات الفعلية.
- `#/supervisor/activity` متابعة الحملات ونداءات التبرع.
- `#/supervisor/reports` التقارير والإحصائيات.

## الحسابات التجريبية السريعة

تعرض صفحة تسجيل الدخول قائمة دخول سريع لا تحتاج إلى كلمة مرور، وتشمل:

- `supervisor@qatra.ps`: مشرف الجهة الصحية.
- `hayat@qatra.ps`: مؤسسة معتمدة بخدمتي طلب الدم وبنك الدم.
- `alamal@qatra.ps`: مؤسسة معتمدة بخدمة طلب الدم فقط.
- `shifa@qatra.ps`: مؤسسة معتمدة بخدمة بنك الدم فقط.
- `donor@qatra.ps`: متبرع بالدم.

عند تجربة الإدخال اليدوي يمكن استخدام كلمة المرور `demo1234`. جميع الحسابات والبيانات محلية وتجريبية ولا تُرسل إلى خادم.

## ملاحظات الربط لاحقًا

- استبدال بيانات `requests` في `src/App.jsx` بطبقة API.
- نقل المصادقة وحالة المستخدم إلى Context أو state manager عند بدء الربط.
- استبدال `setTimeout` في تسجيل الدخول بطلب API حقيقي.
- ربط رفع الوثائق بتخزين آمن والتحقق من النوع والحجم في الخادم.
- تطبيق الصلاحيات في الـBackend؛ إخفاء عناصر الواجهة وحده لا يكفي.
- الألوان معرفة كـCSS variables في بداية `src/styles.css` ومأخوذة من نظام ألوان قطرة.
